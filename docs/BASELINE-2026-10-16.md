# Punkt odniesienia — 2026-10-16 (przed migracją do rdzenia)

Wyniki przekazane przez testującego na Arch Linux / KDE Wayland / Kinect v2; nie są certyfikatem ani powtórnym pomiarem w CI. **Dane identyfikujące konkretny sensor celowo pominięto.**

| Test | Wynik | Zakres dowodu |
| --- | --- | --- |
| USB | urządzenie wykryte | rozpoznanie, nie gwarancja ciągłego streamingu |
| RGB `/dev/video11` | YUYV422 1920×1080, usługa active, 1 odbiorca, `frames` rośnie, `seq_gaps=0`, `output_drops=0` | obraz widoczny w Firefox i zapisanej klatce FFmpeg; `ffplay` podczas testu pokazywał czerń |
| IR `/dev/video10` | podgląd opisany jako bardzo płynny | ocena wizualna; brak zmierzonego FPS/opóźnienia w tym teście |
| Depth | 120 klatek, pary IR+Depth 120/120, brak luk, brak wadliwych formatów | median center Z 783,6 mm, ROI valid 98,9%; Z na osi optycznej, bez porównania z miarką |
| ALSA 4ch | S32_LE, 16000 Hz, 4 kanały, plik WAV 8s | RMS −54,0/−54,3/−54,5/−55,2 dBFS; szczyty około 0,024–0,029; brak dokładnych zer; po odsłuchu i sprawdzeniu wyciszonego wyjścia działa |

### Kryteria regresji w kolejnych zmianach

1. Nie pogorszyć subiektywnej płynności IR; dodać pomiary FPS/opóźnień podczas testu sprzętowego.
2. RGB musi pozostać na żądanie, wyłączać fizyczny sensor bez odbiorców i poprawnie zgłaszać status. Porównać liczniki i poprawność obrazu, nie samą obecność `/dev/video11`.
3. Depth wymaga zgodności IR+Depth, braku luk i poprawnego zakresu Z. Powtórzyć benchmark 120 klatek i dłuższy test.
4. Audio musi nadal dawać dostęp do **oryginalnych** 4 kanałów; opcjonalna konwersja nie może zastąpić RAW.
5. Zawsze mieć działającą poprzednią wersję (tag/branch Git i kopia konfiguracji usług) przed zmianami runtime.
